# AI 설계와 참고 자료

이 프로젝트의 엔진은 TypeScript로 독립 구현했다. 외부 엔진의 코드·가중치·학습 데이터를 사용하지 않았다. 학습형 AI, 프로 수준, Elo, 세계 최강을 주장하지 않는다.

## 확인한 공식 자료

1. **Rapfi — 공식 엔진 설명과 빌드 문서**
   - 원문: https://github.com/dhbloo/rapfi/blob/master/Readme.md
   - 라이선스: https://github.com/dhbloo/rapfi/blob/master/Copying.txt — GPL v3.
   - 확인 내용: 오목/렌주 엔진, alpha-beta와 고전 평가 및 NNUE, CPU 벡터 명령 최적화, WebAssembly 빌드와 스레드/SIMD 옵션. 신경망 평가에는 별도의 네트워크와 설정 파일이 필요하다.
   - 적용: 작은 브라우저 제품에서는 규칙 엔진과 탐색을 먼저 검증하고 Worker로 UI와 분리한다는 설계 판단에 참고했다. Rapfi 소스·평가 가중치·네트워크는 복사하거나 배포하지 않았다. Rapfi와의 기력 비교는 하지 않았다.

2. **David J. Wu — Accelerating Self-Play Learning in Go / KataGo 공식 문서**
   - 논문 원문 링크: https://arxiv.org/abs/1902.10565
   - 직접 확인한 공식 설명: https://github.com/lightvector/KataGo/blob/master/README.md
   - 추가 연구 설명: https://github.com/lightvector/KataGo/blob/master/docs/KataGoMethods.md
   - 라이선스: https://github.com/lightvector/KataGo/blob/master/LICENSE — 주 코드/문서는 MIT 계열 허가, 일부 외부 파일·라이브러리는 별도 조건.
   - 확인 내용: AlphaZero 계열 자기 대국 학습, 정책/가치망과 탐색, CPU/GPU 백엔드, 다양한 판 크기, 별도 모델 파일, 학습 비용 및 MCTS 개선 항목.
   - 적용: 모델 학습/평가/배포 체계 없이 신경망을 도입하지 않기로 했다. 바둑의 결과를 오목 기력의 근거로 사용하지 않는다. 논문 전문을 읽거나 재현했다고 주장하지 않으며, 이번 검토는 공식 프로젝트 설명과 추가 방법 문서를 대상으로 했다. 코드·데이터·모델을 가져오지 않았다.

## 방법 비교와 선택

| 방법 | 시간/메모리 특성 | 복잡도·실행 환경 | 이번 적용 |
| --- | --- | --- | --- |
| Minimax / negamax + alpha-beta | 지수적 탐색, 좋은 수순 정렬로 가지치기; DFS 자체 메모리는 깊이에 비례 | CPU·브라우저 가능, 평가 함수 필요 | 적용 |
| 반복 심화·수순 정렬·상태 캐시 | 완료 깊이마다 결과 보존; 캐시 메모리를 제한해야 함 | 브라우저 가능, 상·하한 캐시 구분 중요 | 적용, 캐시 최대 20,000개 |
| 위협 기반 탐색 / VCF·VCT | 강제 응수에 집중하면 효율적; 여러 위협의 상호작용과 완전성 검증 필요 | 브라우저 가능, 완전한 증명 탐색은 구현 난도가 높음 | 즉시 승리·필수 방어 전체 검사, 방어 수순 최대 2ply 연장만 적용. 완전한 VCF/VCT는 아님 |
| MCTS | rollout 수와 트리 크기에 비례; 희소한 전술을 놓칠 수 있음 | 브라우저 가능, 강한 평가 정책이 있으면 유리 | 미도입 |
| 정책·가치 신경망 / NNUE | 추론 비용·모델 다운로드·가중치 메모리 필요 | 소형 모델은 WASM/WebGPU 가능, 대형 모델은 서버 고려 | 미도입 |
| 자기 대국 학습 + 신경망 탐색 | 많은 대국·평가·GPU 자원 필요; 데이터 분리 필수 | 학습은 별도 인프라, 추론은 모델에 따라 브라우저/서버 | 미도입, 비용 발생 없음 |

## 독립 구현 명세

- 공유 `rules.ts`로 양측 자유 오목(5개 이상)·정확히 5목을 판정한다. 렌주·오프닝 제약은 없다.
- 모든 빈칸에서 즉시 승리 수를 먼저, 다음으로 상대 즉시 승리 수를 검사한다. 이 검사는 주변 후보 축소보다 앞서 실행한다.
- 기존 돌 반경 2칸 후보를 공격/수비 패턴으로 정렬한다. 복합 위협에는 가산점을 주되, 이는 승률이 아니다.
- negamax alpha-beta를 깊이 1부터 반복한다. 상대 응수를 탐색하며, 잎의 필수 방어는 최대 2ply 연장한다.
- 깊이를 끝까지 완료한 결과만 채택한다. 시간/노드 한도에 도달하면 마지막 완료 결과 또는 합법 후보를 쓴다.
- 캐시 키는 225칸 전체 상태 문자열 + 차례 + 규칙 + 연장 잔여량이다. 해시 충돌을 피하며 깊이와 exact/lower/upper bound를 저장한다. 오프닝 상태가 없는 규칙만 지원한다.
- 첫 수는 중앙 근처 5개 후보에서 시드로 선택한다. 동점 순서도 시드로 정한다. 벽시계 제한은 기기 부하에 영향을 받으므로 완전 재현 검사는 넉넉한 시간+고정 깊이/노드 한도를 사용한다.
- Worker를 종료하고 세대 번호를 올려 이전 결과를 무시한다. Worker 실패/5초 응답 없음에는 무거운 탐색 없이 합법 기본 전술 수로 대체하고 사용자에게 알린다.
- 기보 파일의 설정으로 난이도를 복원하며, 게임 도중 선택한 난이도는 몰래 변경하지 않는다. 설정 변경은 새 대국에 적용한다.

| 난이도 | 목표 시간 상한 | 최대 기본 깊이 | 후보 수 |
| --- | ---: | ---: | ---: |
| 입문 | 65ms | 1 | 6 |
| 균형 | 350ms | 3 | 10 |
| 도전 | 1,200ms | 5 | 14 |

이 시간은 탐색 체크 지점 사이의 오버헤드, Worker 시작과 렌더링 시간을 포함하는 하드 실시간 보장이 아니다. 즉시 전술은 시간 제한에 앞서 처리한다. 제한된 후보와 유한 깊이는 장기 강제승리를 놓칠 수 있다. 힌트는 즉시 승리·방어 사실과 추정 후보를 구분한다.

## 평가 원칙

`npm test`로 전술·규칙을 검사한다. `npm run bench`는 세 시작 국면에서 흑백을 바꿔 6판을 완주한다. 양쪽에 동일한 80ms 상한을 주되 한쪽은 깊이 1·후보 6, 다른 쪽은 깊이 3·후보 10이다. 실제 소비 시간은 다르며 JSON에 기록한다. 이것은 현재 구현의 얕은 탐색 기준선과의 비교다. 기존 게임/이전 출시 엔진이 없으므로 이전 버전 대비 개선율은 산출할 수 없다.

결과, 모든 기보, 평균/p95 지연, 메모리 스냅샷, 승리 비율 Wilson 구간은 `benchmark.json`에 남긴다. 6판은 작은 기능 점검 표본이다. 같은 시작 국면의 교대 대국은 독립 표본으로 보기 어려우므로 해당 구간도 참고용이며 일반 기력 추정에 쓰지 않는다.

후속 연구: 독립 전술 세트 확대 → 더 많은 시작 국면/노드 예산 평가 → VCF/VCT 완전성 검증 → 필요할 때 별도 승인과 데이터 분리를 거친 모델 학습 순서로 진행한다.
