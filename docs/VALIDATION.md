# 검수 기록 · 2026-10-24

## 구현 결과

README만 있던 `herongio/desktop-tutorial`에 새 게임을 구현했다. 기존 오목 코드·실행 시스템·이전 AI 버전은 없었다. 소스와 테스트는 이 저장소에만 추가했다. 원격 커밋/푸시·PR·운영 배포는 하지 않았다. 르미에게 직접 전달하지 않았으며 이 문서는 재현 가능한 검수를 위한 자료다.

로그인 없이 AI와 첫 수부터 대국할 수 있다. 자유 오목/정확히 5목, AI/2인 대국, 3개 난이도, 색 선택, 새 판/무르기/기권/일시정지, 저장 복원, JSON 기보, 복기/분기/힌트, 연습 4개, 3개 테마, 소리/음소거, 터치 확인/키보드 조작을 구현했다. 모든 메뉴와 버튼은 실제 상태 및 동작에 연결되어 있다.

구현 파일과 실행 명령은 [README](../README.md), AI 설정과 참고 문서/라이선스 범위는 [AI-RESEARCH.md](AI-RESEARCH.md)에 정리했다.

### 실제 브라우저에서 수행한 16가지 검사

1. 같은 기기 2인 대국을 9수 승리까지 진행 → 승리선 5개 표시 → 종료 후 착수 차단 → 무르기 → 새 게임.
2. AI 계산 중 무르기·일시정지 → 늦은 추가 착수 없음 → 계속하기 응수 → 사람 백돌로 새 게임.
3. AI 즉시 승리 국면 가져오기 → 실제 Worker가 승리 수 착수 → 새로고침 후 종료 상태 복원.
4. 4수 착수 → 새로고침 자동 복원 → 처음/다음 복기 → 다른 수 분기 → 원본 4수 복원 → 기록 보관·다시 열기.
5. 기보 다운로드 → 새 대국 → 파일 재입력 → 동일 판 복원 → 중복 좌표 기보 거부, 기존 판 유지.
6. 방향키·Enter 착수 → 힌트와 설명 → 모던/다크 테마 → 연습 오답/정답 → 원래 대국 복귀.
7. Worker 로딩을 의도적으로 실패시킴 → 합법 기본 전술 대체 수 및 알림.
8. 저장소 쓰기를 의도적으로 거부 → 오류 알림, 대국은 계속 가능.
9. 정확히 5목 설정 적용 → 기권 → 종료 뒤 입력 차단.
10. 데스크톱 대표 화면 캡처, 가로 넘침 없음.
11. 종료 요청을 무시하고 늦게 응답하는 Worker를 모사 → 새 게임/규칙 변경 후 오래된 수 무시.
12. 더블클릭은 1수만 적용 → 드래그 중단 이벤트 뒤 클릭은 착수하지 않음.
13. 데스크톱에서 실제 보드 입력으로 AI 대국 전체 완주. 사람 측 입력은 재현용 얕은 탐색기가 선택.
14. 연속 공격 문제: 공격 → 상대의 실제 방어 → 남은 승리 수까지 완료.
15. 모바일 터치 확인으로 2인 대국 전체 완주 → 결과 화면 캡처 → 회전 후 모서리 O1 착수 확인.
16. 모바일 터치 확인으로 실제 AI 대국 전체 완주. 사람 측 입력은 재현용 얕은 탐색기가 선택.

브라우저에서 게임 엔진과 UI를 실제로 실행한 자동 대국이다. 사람이 물리적 휴대전화를 들고 플레이한 검수라고 표현하지 않는다.

## AI 비교 결과

원본: [benchmark.json](benchmark.json). 이전 출시 엔진이 없으므로 **이전 버전 대비 개선율은 없음**. 현재 구현의 얕은 탐색 설정을 기준선으로 삼았다.

- 자유 오목, 세 시작 국면 × 흑백 교대 = 6판. 최대 225수까지 실제 종료 판정을 사용.
- 양측 시간 상한 80ms. 기준선: 깊이 1/후보 6, 탐색: 깊이 3/후보 10. 두 엔진의 시간 상한은 같지만 실제 소비 시간은 다르다.
- 탐색 측 **6승 0무 0패**. 9·16·9·34·29·42수에 종료.
- 탐색 측 63회: 평균 **19.58ms**, p95 **35.96ms**, 최대 **37.83ms**.
- 기준선 60회: 평균 **0.55ms**, p95 **1.07ms**.
- 단순 승리 비율 Wilson 95% 참고 구간 약 **61.0–100%**. 6판의 작은 표본이며 교대 국면은 독립적이지 않다. 일반 기력·공식 승률·Elo의 근거로 사용하지 않는다.
- Node 힙 스냅샷 8,433,240 → 16,032,856 bytes. GC 시점과 임시 탐색 메모리를 포함하며 장기 누수 검증은 아니다.

시드를 사용하지만 벽시계 제한은 하드웨어·부하에 따라 탐색 완료 깊이를 바꿀 수 있다. 반복성 단위 검사는 충분한 시간과 고정 깊이를 사용한다. 전술 검사는 모든 난이도의 즉시 승리/필수 방어와 정확히 5목 규칙을 확인한다.

원본: [browser-performance.json](browser-performance.json). `npm run preview`로 빌드 결과를 제공하고 Chromium에서 실제 AI 응수 및 힌트를 실행했다.

| 국면 | 힌트 엔진 시간 | UI 요청~확인 시간 | 탐색 중 테마 클릭 완료 | 최대 프레임 간격 | 50ms 이상 메인 스레드 작업 |

## 검수자가 재현하는 순서

1. README의 설치/실행 명령을 수행한다. 기본 화면에서 보드 중앙에 착수하고 AI가 한 번만 응수하는지 확인한다.
2. ‘착수 확인’을 켜고 다른 위치를 선택한다. 확인 전 돌이 놓이지 않는지 확인한다. 모바일에서는 기본으로 켜진다.
3. ‘도전’을 선택하고 새 대국 시작. 착수 직후 무르기 또는 새 게임을 누른다. 이전 AI 결과가 새 판에 나타나면 실패다.
4. ‘친구와 둘이’로 새 판 시작. A15, A14, B15, C14, C15, E14, D15, G14, E15 순서로 놓는다. 흑 승리와 추가 착수 차단을 확인한다.
5. 복기의 처음/이전/다음/마지막을 이동한다. ‘다른 수 놓기’ 후 ‘대국으로’ 복귀해 원본이 바뀌지 않았는지 확인한다.
6. 기보 내보내기 → 새 게임 → 가져오기로 동일 상태를 복원한다. JSON에서 좌표 하나를 중복시켜 불러오면 거부되어야 한다.
7. 연습실의 4개 문제에서 힌트와 복수 정답을 확인한다. 연속 공격은 특정 좌표 하나를 정답으로 고정하지 않고 실제 승리/위협 수를 검사한다.
8. 우드/모던/다크, 음소거/켜기, 키보드 이동/착수와 브라우저의 동작 줄이기 설정을 확인한다.

## 한계와 다음 우선순위

- **미검수**: 실제 iOS Safari·Android 기기·Firefox, 물리적 핀치/스크롤 제스처, 스크린리더 실사용, 실제 스피커 음질, 장시간 메모리/배터리, 실제 이용자 사용성. Chromium 자동화와 코드 검사로 대체했다고 주장하지 않는다.
- **AI 한계**: 후보 축소와 유한 깊이 때문에 장기 전술을 놓칠 수 있다. 완전한 VCF/VCT 증명, 신경망, 자기 대국 학습은 없다. 더 많은 독립 전술·국면과 통제된 노드 예산 평가가 다음 우선순위다.
- **복기 한계**: 선택한 장면의 추천/실제 수 비교와 즉시 승리 누락만 판별한다. 전 기보 자동 실수 등급·승률 그래프는 없다.
- **미구현 확장**: 렌주 금수/공식 오프닝, 온라인/계정/랭킹/동기화, 설치형 PWA/오프라인 재로딩. 기존 핵심 대국과 구분한다.
- **성능 후속**: 중저가 물리 기기에서 측정하고 시간 예산/후보 정렬을 조정한다. 현재 수치는 해당 클라우드 Chromium의 측정치다.
- 원격 반영·운영 배포·환경 게시는 아직 수행하지 않았다. 추가 비용은 발생시키지 않았다.
- 클라우드 환경 초안의 `install_script`와 `start_skill`을 저장했다. 설치는 고정 lockfile의 `npm ci`와 빌드, 시작은 기존 checkout에서 Vite 실행 및 실제 Worker 승리/복원 검사다. 저장 성공을 확인했지만 게시한 것은 아니다. 재사용하려면 환경 설정에서 초안을 검토·저장한 뒤 게시한다.

이 기록은 핵심 게임 신규 구현과 검증 결과이며, 모든 장기 고도화 목표를 완료했다는 보고가 아니다.
